# Настройка Figma MCP в MultiTool (полный автопилот)

Пользователь кинул файл/ссылку с инструкцией по подключению Figma MCP или
просит, чтобы инструменты `figma_*` работали в чатах. Твоя задача — довести
настройку до рабочего состояния, самому внося правки, и оставить одиночный
понятный шаг пользователю (обычно только «перезапусти MultiTool»).

## Ключевая идея (почему всё так, а не иначе)

MultiTool построен на том же движке, что и opencode: он читает тот же формат
`opencode.json` и хранит OAuth-токены MCP в том же формате `mcp-auth.json`.
Метод подключения к Figma — `type: "remote"`, `url: https://mcp.figma.com/mcp`:
это **не** локальный сервер и **не** фигмовский PAT (`figd_...`), а OAuth,
прописанный внутри приложения. Поэтому отдельные пути могут быть заняты
копией из другого config-файла (например, у пользователя может стоять и
opencode, и этот путь уже пройден там). Ищи и переноси уже готовые токены
прежде чем просить что-то вводить руками.

Из этого вытекает весь алгоритм: проверить 3 вещи (конфиг, токен, срок),
починить недостающее, попросить перезапуск.

## Шаги

### 1. Определи окружение

Рабочий стол/приложение — MultiTool. Его глобальный конфиг и хранилище:

```
CONFIG   = %USERPROFILE%\.config\gigatool\opencode.json
AUTH     = %USERPROFILE%\.local\share\gigatool\mcp-auth.json
```

Рядом может существовать конфиг старого/параллельного opencode (того же движка):

```
OCONFIG  = %USERPROFILE%\.config\opencode\opencode.json
OAUTH    = %USERPROFILE%\.local\share\opencode\mcp-auth.json
```

> Под `%USERPROFILE%` понимается домашняя папка Windows текущего пользователя
> (обычно `C:\Users\<имя-пользователя>`). В PowerShell той же переменной
> отвечает `$env:USERPROFILE`. Не зашивай в скрипты конкретное имя пользователя.

Проверь существование обоих вариантов `bash`/`Test-Path`. Пользователь может
ссылаться на любой из них как на эталон.

### 2. Проверь секцию `mcp` в конфиге MultiTool

Прочитай `CONFIG` (это JSON). В нём должен быть объект:

```json
"mcp": {
  "figma": {
    "type": "remote",
    "url": "https://mcp.figma.com/mcp",
    "enabled": true
  }
}
```

Если секции `mcp` нет вообще или нет ключа `figma` — добавь/вправь. При правке
не трогай остальные ключи (`permission` и прочее), сохраняй их без изменений.

### 3. Проверь и, если надо, перенеси OAuth-токен

`AUTH` должен содержать объект `figma` с полями `clientInfo` (clientId,
clientSecret) и `tokens` (accessToken, refreshToken, expiresAt). Ключ может
быть `figma` (в нижнем регистре — так движок ожидает).

- Если токен есть и его `expiresAt` в будущем — ок, ничего не делай.
- Если токена нет, `expiresAt` в прошлом ИЛИ в `AUTH` пустовато — посмотри
  `OAUTH`. Если там есть валидный свежий `figma` (тот же json-формат) —
  скопируй из него в `AUTH` блок `figma` целиком (вместе с clientInfo+tokens).
- Если свежего токена нигде нет — сообщи пользователю, что нужно пройти OAuth
  заново (бразуер → «Allow»), и останови правки конфига до этого.

> ВАЖНО про собеседника конфига: если в `AUTH` рядом с `figma` есть отдельный
> ключ со `codeVerifier` (например `Figma`) — подержи его/восстанови, он
> связан с OAuth-потоком, удалять его не нужно. При перезаписи файла с
> сохранением этого ключа пиши файл в UTF-8.

### 4. Запись в файл, заблокированный запущенным приложением

Пока MultiTool запущен, `AUTH` держится открытым и запись может падать с
`Access to the path ... is denied`, а прав на запись у обычной сессии может не
быть (ACL: `Users: RX`). Тогда:

1. Сначала проверь, правда ли файл заблокирован: попробуй
   `[System.IO.File]::Open($p, Open, ReadWrite, ReadWrite)` — если исключение,
   читай дальше.
2. Готовь **elevated**-запуск через UAC (надёжнее всего и не требует никаких
   прав рукой). Мысль: записать правильный json из временного `.ps1`-скрипта,
   запущенного от имени администратора. Используй `Start-Process ... -Verb
   RunAs -Wait`. Пример такого сценария для записи нового содержимого файла:

   ```powershell
   $script = @'
   $gtPath = Join-Path $env:USERPROFILE ".local\share\gigatool\mcp-auth.json"
   # ... собери $newJson как строку JSON с блоком figma ...
   Set-Content -Path $gtPath -Value $newJson -Encoding UTF8 -Force
   $check = Get-Content $gtPath -Raw
   if ($check -match '"expiresAt":\s*([0-9.]+)') {
     $e=[double]$Matches[1]
     Write-Output ("OK: токен Figma обновлён, срок до " + [DateTimeOffset]::FromUnixTimeMilliseconds([long]($e*1000)).ToLocalTime())
   }
   '@
   $tempScript = [System.IO.Path]::GetTempFileName() + '.ps1'
   Set-Content -Path $tempScript -Value $script
   Start-Process -FilePath 'powershell' -ArgumentList "-NoProfile -ExecutionPolicy Bypass -File `"$tempScript`"" -Verb RunAs -Wait
   Remove-Item $tempScript -Force -ErrorAction SilentlyContinue
   ```

   UAC-запрос выскочит в окне («Разрешить»), пользователь жмёт — без закрытия
   MultiTool. После — перечитай `AUTH` и убедись, что `expiresAt` правильный.

> Запись в `CONFIG` (opencode.json) обычно не заблокирована и не требует UAC —
> правится обычным edit/write. UAC нужен прежде всего для `AUTH`.

### 5. Финиш и проверка

- Скажи пользователю перезапустить MultiTool и, если хочешь, проверь сам через
  `figma_whoami` — но только ПОСЛЕ перезапуска (в текущем чате инструменты
  Figma после входа могут появиться только в новой сессии).
- Кратко: что было сделано (конфиг / токен / оба), куда перезапустить, как
  проверить (`figma_whoami`).

## Чек-лист результата

- [ ] В `CONFIG` есть `mcp.figma` (remote, url верный, enabled: true).
- [ ] В `AUTH` есть блок `figma` с clientInfo+tokens, `expiresAt` в будущем.
- [ ] При перезаписи сохранён `codeVerifier`-ключ, если был.
- [ ] Файлы записаны (обычно правки конфига — да; правка AUTH под UAC).
- [ ] Пользователь получил одну инструкцию: перезапустить MultiTool.

## Похожие задачи — это НЕ сюда

- «Переименуй слои» / «наведи порядок в Figma» → навык `figma-layer-naming`.
- Создание/правка Figma-файлов → используй инструменты `figma_*` напрямую.
- Подключение MCP других сервисов → не входит; тут только Figma.
