# Настройка Figma MCP (полный автопилот)

Пользователь кинул файл/ссылку с инструкцией по подключению Figma MCP или
просит, чтобы инструменты `figma_*` работали в чатах. Твоя задача — довести
настройку до рабочего состояния, самому внося правки, и оставить одиночный
понятный шаг пользователю (обычно только «перезапусти приложение»).

## Ключевая идея (почему всё так, а не иначе)

Агенты на движке OpenCode читают конфиг MCP в формате `opencode.json` и хранят
OAuth-токены в том же формате `mcp-auth.json`. Figma подключается как
`type: "remote"`, `url: https://mcp.figma.com/mcp` — это **не** локальный сервер
и **не** фигмовский PAT (`figd_...`), а OAuth.

**Сначала официальный путь.** Figma с недавнего времени официально поддерживает
OpenCode в своём аллаулисте OAuth-клиентов (см. Figma MCP docs, таблица
поддерживаемых клиентов). Поэтому для чистого OpenCode нативный OAuth должен
работать из коробки: достаточно прописать remote-сервер и дать движку самому
пройти авторизацию. Через нативный OAuth регистрируешься как `opencode`.

**Запасной путь только если официальный не сработал.** MultiTool и другие
агенты на том же движке — отдельные продукты со своим host-идентификатором и
своим `clientId` при OAuth-регистрации. Figma добавляла в аллаулист конкретно
«OpenCode»; если твой агент регистрируется под другим host-именем (например
`gigatool`), Figma может по-прежнему отклонять его динамическую регистрацию.
Тогда и нужен fallback: либо готовый OAuth-токен, зарегистрированный под
allowlisted-клиентом (уже лежащий в конфиге «соседнего» OpenCode), либо токен
через `mcp-auth-helper`, который регистрируется под allowlisted-именем (Codex).

Порядок всегда такой: **сначала официальное, потом обход**. Запланируй
ресурсы под обе ветки, но старайся не листать пользователя по нескольким
перезапускам — сначала закончи возможно-официальным путём.

## Шаги

### 1. Определи окружение (какой агент/хост)

Агент на движке OpenCode хранит конфиг и токены в папке своего host-имени.
Обычно это один из двух:

```
CONFIG  = %USERPROFILE%\.config\gigatool\opencode.json     # MultiTool
AUTH    = %USERPROFILE%\.local\share\gigatool\mcp-auth.json
```
```
CONFIG  = %USERPROFILE%\.config\opencode\opencode.json     # OpenCode
AUTH    = %USERPROFILE%\.local\share\opencode\mcp-auth.json
```

Определи хост по имени агента в чате / работающей папке / тому, какие каталоги
реально существуют (`Test-Path`). Формально оба пути = `%USERPROFILE%\.config\<host>\opencode.json`
и `%USERPROFILE%\.local\share\<host>\mcp-auth.json`, где `<host>` = `gigatool` | `opencode` | иное.

«Соседний» конфиг того же движка (эталон из основного OpenCode) пригодится как
источник готового токена для fallback-пути:

```
OCONFIG = %USERPROFILE%\.config\opencode\opencode.json
OAUTH   = %USERPROFILE%\.local\share\opencode\mcp-auth.json
```

> `%USERPROFILE%` — домашняя папка Windows текущего пользователя (обычно
> `C:\Users\<имя-пользователя>`); в PowerShell это `$env:USERPROFILE`.
> **Никогда не зашивай в скрипты конкретное имя пользователя или хост.**

### 2. Проверь и пропиши сервер в конфиге агента

Читай `CONFIG` (JSON) и убедись, что в нём есть секция:

```json
"mcp": {
  "figma": {
    "type": "remote",
    "url": "https://mcp.figma.com/mcp",
    "enabled": true
  }
}
```

Если секции `mcp` нет или нет ключа `figma` — добавь/вправь. При правке не
трогай остальные ключи (`permission` и прочее), сохраняй их без изменений.
Запись в `CONFIG` обычно не блокируется и не требует UAC — правится через
edit/write.

### 3. ОФИЦИАЛЬНЫЙ ПУТЬ: попробуй нативный OAuth

После того как сервер прописан, перезапусти агента и дай движку самому пройти
авторизацию (нативный OAuth). Для чистого OpenCode Figma теперь это
поддерживает. Если текущая сессия уже поднята после прописывания сервера —
проверь, появились ли инструменты `figma_*` и сработает ли `figma_whoami`.

- **Завелось** (tools есть, `figma_whoami` вернул профиль без ошибок) → финиш
  по чек-листу, можно не делать обход. Заверши.
- **Не завелось** (нет токена в `AUTH`, `figma_whoami`/инструменты падают с
  500 / авторизация отклонена / tools не появились после рестарта) → переходи
  на fallback (шаг 4). Это ожидаемо для агентов с неallowlisted host-именем
  (например MultiTool/`gigatool`).

### 4. FALLBACK: перенос готового OAuth-токена

Используй только если шаг 3 не сработал.

`AUTH` должен содержать объект `figma` с полями `clientInfo` (clientId,
clientSecret) и `tokens` (accessToken, refreshToken, expiresAt). Ключ —
`figma` (в нижнем регистре, так движок ожидает).

- Токен есть и `expiresAt` в будущем → ок, ничего не делай.
- Токена нет, `expiresAt` в прошлом ИЛИ в `AUTH` пустовато → посмотри `OAUTH`
  (соседний конфиг того же движка). Если там есть валидный свежий `figma`
  (тот же json-формат) — скопируй блок `figma` целиком (clientInfo+tokens) в
  `AUTH`.
- Свежего токена нигде нет → предложи пройти OAuth через `mcp-auth-helper`
  (sdaoudi/mcp-auth-helper на GitHub), который регистрируется под
  allowlisted-именем (Codex): обычно
  `node dist/index.js auth figma --url https://mcp.figma.com/mcp`
  (браузер → «Allow»). После этого токен появится в конфиге, куда писал helper.

> ВАЖНО про соседние ключи конфига: если в `AUTH` рядом с `figma` есть отдельный
> ключ со `codeVerifier` (например `Figma`) — сохрани его / восстанови при
> перезаписи; он связан с OAuth-потоком, удалять его не нужно. Пиши файл в UTF-8.

### 5. Запись в файл, заблокированный запущенным приложением

Пока приложение запущено, `AUTH` может держаться открытым, и запись падает с
`Access to the path ... is denied`, а прав на запись у обычной сессии может не
быть (ACL: `Users: RX`). Тогда:

1. Проверь, действительно ли файл заблокирован:
   `[System.IO.File]::Open($p, Open, ReadWrite, ReadWrite)` — если исключение,
   продолжай с пункта 2.
2. Пиши через elevated-запуск (UAC) — надёжнее всего и не требует прав рукой.
   Запиши правильный json из временного `.ps1`, запущенного от имени
   администратора, через `Start-Process ... -Verb RunAs -Wait`. Пример:

   ```powershell
   $script = @'
   $gtPath = Join-Path $env:USERPROFILE ".local\share\gigatool\mcp-auth.json"  # git. sub host: gigatool / opencode / иное
   # ... собери $newJson как строку JSON с блоком figma ...
   Set-Content -Path $gtPath -Value $newJson -Encoding UTF8 -Force
   $check = Get-Content $gtPath -Raw
   if ($check -match '"expiresAt":\s*([0-9.]+)') {
     $e=[double]$Matches[1]
     Write-Output ("OK: токен Figma обновлён, срок до " + [DateTimeOffset]::FromUnixTimeMilliseconds([long]($e*1000)).ToLocalTime())
   }
   '@
   $tempScript = [System.IO.Path]::GetTempFileName() + '.ps1'
   Set-Content -Path $tempScript -Value $script
   Start-Process -FilePath 'powershell' -ArgumentList "-NoProfile -ExecutionPolicy Bypass -File `"$tempScript`"" -Verb RunAs -Wait
   Remove-Item $tempScript -Force -ErrorAction SilentlyContinue
   ```

   UAC-запрос выскочит в окне («Разрешить»), пользователь жмёт — без закрытия
   приложения. После — перечитай `AUTH` и убедись, что `expiresAt` правильный.

   > Запись в `CONFIG` (opencode.json) обычно не заблокирована и не требует UAC —
   > правится обычным edit/write. UAC нужен прежде всего для `AUTH`.

### 6. Финиш и проверка

- Скажи пользователю перезапустить агента/приложение (если ещё не перезапускал
  на шаге 3). Проверь через `figma_whoami`. Инструменты `figma_*` в текущем чате
  могут появиться только после рестарта (новая сессия).
- Кратко отчитайся: какой путь сработал (официальный OAuth или fallback-перенос
  токена), что было сделано, что перезапустить, как проверить.

## Чек-лист результата

- [ ] Определён хост (`gigatool` / `opencode` / иной) и правильные `CONFIG`/`AUTH`.
- [ ] В `CONFIG` есть `mcp.figma` (remote, url верный, enabled: true).
- [ ] Сначала пробовался официальный нативный OAuth (шаг 3).
- [ ] Нативный не завёлся или завёлся — fallback применён только при неудаче.
- [ ] В `AUTH` есть блок `figma` с clientInfo+tokens, `expiresAt` в будущем.
- [ ] При перезаписи сохранён `codeVerifier`-ключ, если был.
- [ ] Пользователь получил одну инструкцию: перезапустить приложение.
